# Pascal-S 编译器需求分析报告

## 1. 项目概述

### 1.1 项目背景
本项目旨在开发一个Pascal-S语言编译器，采用源到源翻译（Source-to-Source Translation）的方式，将Pascal-S代码转换为C语言代码，再通过现有的C编译器生成可执行文件。

### 1.2 项目目标
- 实现完整的Pascal-S语法分析和语义分析
- 生成等价的、可读性良好的C语言代码
- 支持Pascal-S语言的核心特性
- 提供友好的错误提示和诊断信息
- 确保生成的C代码能够正确编译和运行

### 1.3 开发语言
C/C++

## 2. Pascal-S 语言特性需求

### 2.1 数据类型
- **基本类型**
  - `integer`: 整型
  - `real`: 实数类型
  - `char`: 字符类型
  - `boolean`: 布尔类型
  
- **构造类型**
  - 数组（Array）：一维和多维数组
  - 记录（Record）：结构体类型
  
- **用户定义类型**
  - 枚举类型（Enumeration）
  - 子界类型（Subrange）

### 2.2 程序结构
- 程序头（Program Header）
- 常量声明部分（Const Declaration）
- 类型声明部分（Type Declaration）
- 变量声明部分（Var Declaration）
- 过程和函数声明（Procedure/Function Declaration）
- 主程序体（Main Program Block）

### 2.3 语句支持
- **赋值语句**: `:=`
- **条件语句**: `if-then-else`
- **循环语句**: 
  - `while-do`
  - `repeat-until`
  - `for-to-do` / `for-downto-do`
- **复合语句**: `begin-end`
- **过程调用**: 支持参数传递（值传递和引用传递）
- **输入输出**: `read`, `readln`, `write`, `writeln`

### 2.4 表达式和运算符
- **算术运算符**: `+`, `-`, `*`, `/`, `div`, `mod`
- **关系运算符**: `=`, `<>`, `<`, `<=`, `>`, `>=`
- **逻辑运算符**: `and`, `or`, `not`
- **运算符优先级**: 符合Pascal标准

### 2.5 函数和过程
- 支持函数定义和调用
- 支持过程定义和调用
- 支持递归调用
- 支持局部变量和参数
- 支持值参数（Value Parameters）和变参数（Var Parameters）

## 3. 功能性需求

### 3.1 词法分析（Lexical Analysis）
- **FR-1.1**: 识别Pascal-S的所有关键字
- **FR-1.2**: 识别标识符（变量名、函数名等）
- **FR-1.3**: 识别常量（整数、实数、字符、字符串）
- **FR-1.4**: 识别运算符和分隔符
- **FR-1.5**: 过滤注释（`{...}` 和 `(*...*)`）
- **FR-1.6**: 处理空白字符和换行
- **FR-1.7**: 报告词法错误（非法字符、未闭合注释等）

### 3.2 语法分析（Syntax Analysis）
- **FR-2.1**: 构建抽象语法树（AST）
- **FR-2.2**: 验证程序结构的正确性
- **FR-2.3**: 检测语法错误并报告行号和列号
- **FR-2.4**: 支持错误恢复机制
- **FR-2.5**: 提供详细的语法错误信息

### 3.3 语义分析（Semantic Analysis）
- **FR-3.1**: 符号表管理（变量、函数、类型）
- **FR-3.2**: 作用域检查（局部/全局变量）
- **FR-3.3**: 类型检查和类型推导
- **FR-3.4**: 变量声明检查（重复声明、未声明使用）
- **FR-3.5**: 函数/过程调用检查（参数数量、类型匹配）
- **FR-3.6**: 数组边界检查
- **FR-3.7**: 常量表达式求值

### 3.4 代码生成（Code Generation）
- **FR-4.1**: 将Pascal-S类型映射到C类型
- **FR-4.2**: 生成C语言的变量声明
- **FR-4.3**: 生成C语言的函数定义
- **FR-4.4**: 转换Pascal语句为C语句
- **FR-4.5**: 处理Pascal特有语法（如`begin-end`转为`{}`）
- **FR-4.6**: 生成标准C代码（符合C99或C11标准）
- **FR-4.7**: 保持代码可读性（适当的缩进和注释）
- **FR-4.8**: 生成必要的头文件包含（`stdio.h`, `stdlib.h`等）

### 3.5 错误处理
- **FR-5.1**: 词法错误检测和报告
- **FR-5.2**: 语法错误检测和报告
- **FR-5.3**: 语义错误检测和报告
- **FR-5.4**: 提供错误位置（文件名、行号、列号）
- **FR-5.5**: 提供错误修复建议
- **FR-5.6**: 支持多错误报告（不在第一个错误处停止）

### 3.6 输入输出
- **FR-6.1**: 从文件读取Pascal-S源代码
- **FR-6.2**: 输出C语言源代码到文件
- **FR-6.3**: 支持命令行参数指定输入输出文件
- **FR-6.4**: 可选的中间表示输出（AST、符号表等）

## 4. 非功能性需求

### 4.1 性能需求
- **NFR-1.1**: 编译速度：中等规模程序（1000行）应在1秒内完成
- **NFR-1.2**: 内存使用：合理的内存占用，避免内存泄漏
- **NFR-1.3**: 生成代码效率：生成的C代码应具有合理的执行效率

### 4.2 可靠性需求
- **NFR-2.1**: 编译器不应崩溃，即使输入有错误
- **NFR-2.2**: 生成的C代码应能通过标准C编译器编译
- **NFR-2.3**: 对于合法的Pascal-S程序，生成的代码应保持语义等价

### 4.3 可维护性需求
- **NFR-3.1**: 代码结构清晰，模块化设计
- **NFR-3.2**: 充分的代码注释
- **NFR-3.3**: 遵循C/C++编码规范
- **NFR-3.4**: 提供开发文档和用户手册

### 4.4 可移植性需求
- **NFR-4.1**: 支持Windows、Linux、macOS平台
- **NFR-4.2**: 使用标准C/C++特性，避免平台特定代码
- **NFR-4.3**: 使用跨平台构建工具（如CMake）

### 4.5 可扩展性需求
- **NFR-5.1**: 易于添加新的语言特性
- **NFR-5.2**: 支持优化选项的扩展
- **NFR-5.3**: 模块化设计便于功能增强

## 5. 系统约束

### 5.1 技术约束
- 使用C/C++语言实现
- 生成的目标代码为C语言（C99或C11标准）
- 使用标准库，最小化第三方依赖

### 5.2 开发约束
- 开发周期：预计8-12周
- 团队规模：3-5人
- 使用版本控制系统（Git）

### 5.3 运行环境
- 操作系统：Windows/Linux/macOS
- C编译器：GCC、Clang或MSVC
- 最小内存：256MB
- 磁盘空间：50MB

## 6. 用户界面需求

### 6.1 命令行界面
```bash
pascal-s-compiler [options] <input_file>

选项:
  -o <output_file>    指定输出C文件名
  -ast                输出抽象语法树
  -sym                输出符号表
  -v, --verbose       详细输出模式
  -h, --help          显示帮助信息
  --version           显示版本信息
```

### 6.2 输出格式
- 标准输出：编译进度和摘要信息
- 错误输出：错误和警告信息
- 文件输出：生成的C代码文件

- Pascal-S源代码文件（.pas或.p扩展名）

### 7.2 输出数据

## 9. 示例转换

### 9.1 简单程序示例

**Pascal-S 输入:**
```pascal
program Example;
var
  x, y: integer;
begin
  x := 10;
  y := 20;
  writeln(x + y);
end.
```

**C 输出:**
```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int x, y;
    x = 10;
    y = 20;
    printf("%d\n", x + y);
    return 0;
}
```

- **风险**: 语义分析复杂度高

### 12.2 进度风险
- **风险**: 开发时间可能超出预期
- **应对**: 采用迭代开发，优先实现核心功能

### 12.3 质量风险
- **风险**: 生成代码可能存在语义不等价
- **应对**: 建立完善的测试体系，充分测试
